# fa-console

> **با یک import، فارسیِ درست در کنسول ویندوز.**

[English](README.md) | **فارسی**

[![PyPI version](https://img.shields.io/pypi/v/fa-console.svg)](https://pypi.org/project/fa-console/)
[![Python](https://img.shields.io/pypi/pyversions/fa-console.svg)](https://pypi.org/project/fa-console/)

`fa_console` کارکردن `print()` و `input()` پایتون با متن فارسی را در ویندوز
**خودکار** درست می‌کند — بدون وابستگی اجباری و بدون تغییر در کد شما؛ فقط یک
`import`.

مشکل فارسی در کنسول ویندوز دو لایه‌ی مستقل دارد و این پکیج هر دو را حل می‌کند:

| لایه | بدون `fa_console` | با `fa_console` |
|------|-------------------|-----------------|
| **انکودینگ** | کدپیج قدیمی کنسول (۷۲۰ / ۱۲۵۲ / …) متن UTF-8 را در پایپ و ریدایرکت خراب می‌کند؛ برنامه با `UnicodeEncodeError` می‌میرد | کدپیج کنسول روی UTF-8 (۶۵۰۰۱) تنظیم می‌شود؛ استریم‌های استاندارد به UTF-8 بازپیکربندی می‌شوند؛ فرایندهای فرزند هم با `PYTHONUTF8` تضمین می‌شوند |
| **نمایش** | کنسول کلاسیک (`conhost`) حروف را به هم نمی‌چسباند و راست‌به‌چپ نمی‌چیند؛ متنِ درست، وارونه و جدا‌جدا دیده می‌شود | هر خروجی به «شکل دیداری» تبدیل می‌شود (شکل‌دهی حروف + چینش دوجهته) و حروف چسبیده و راست‌به‌چپ دیده می‌شوند؛ هنگام تایپ هم `fa_input` به‌صورت زنده درست نشان می‌دهد |

**قبل**

```
>>> print("سلام دنیا")
ﺎﯿﻧﺩ ﻡﻼﺳ          # جدا‌جدا، وارونه، ناخوانا
```

**بعد**

```
>>> import fa_console
>>> print("سلام دنیا")
سلام دنیا          # چسبیده، راست‌به‌چپ، خوانا
```

## ویژگی‌ها

- ✅ **راه‌اندازی یک‌خطی** — `import fa_console` همه‌چیز را در لحظه‌ی import پیکربندی می‌کند
- ✅ **لایه‌ی انکودینگ** — کدپیج UTF-8، بازپیکربندی `sys.stdin`/`sys.stdout`/`sys.stderr`
  (حتی `PYTHONIOENCODING` خراب را خنثی می‌کند) و تثبیت متغیرهای محیطی برای فرایندهای فرزند
- ✅ **لایه‌ی نمایش** — تبدیل منطقی→دیداری (شکل‌دهی حروف به Arabic Presentation Forms +
  چینش دوجهته) روی **همه‌ی** خروجی‌ها، از جمله `print` معمولی و f-string ها
- ✅ **دو موتور تبدیل** — در صورت نصب بودن `arabic-reshaper` و `python-bidi` از آن‌ها
  استفاده می‌شود (UAX #9 کامل، لاگاتور «لا»، قواعد فارسی)؛ در غیر این صورت موتور داخلیِ
  بدون وابستگی
- ✅ **نمایش زنده هنگام تایپ** — `fa_input()` حروف را همان لحظه که تایپ می‌کنید چسبیده و
  راست‌به‌چپ نشان می‌دهد؛ رفتار سازگار با `input()` استاندارد (`KeyboardInterrupt` / `EOFError`)
- ✅ **تشخیص هوشمند** — Windows Terminal و خروجی ریدایرکت‌شده دست‌نخورده می‌مانند؛
  ترمینال VS Code هم مانند کنسول کلاسیک تبدیل نمایشی می‌گیرد (موتور xterm.js
  چینش دوجهته‌ی قابل اعتمادی ندارد)
- ✅ **امن در برابر کیبورد عربی** — حروف تایپ‌شده با چیدمان عربی (ي / ك)، اعداد فارسی /
  عربی / ASCII و جداکننده‌های عددی (٫ ٬ . ,) همگی در تبدیل نمایش درست مدیریت می‌شوند؛
  `fa_normalize()` برای یکسان‌سازی در مقایسه و ذخیره‌سازی در دسترس است
- ✅ **طراحی fail-open** — ماژول هرگز برنامه‌ی میزبان را نمی‌شکند؛ هر خطای داخلی از طریق
  لاگر `fa_console` ثبت می‌شود و به رفتار استاندارد برمی‌گردد
- ✅ **بدون وابستگی اجباری** — فقط کتابخانه‌ی استاندارد، پایتون 3.8 به بالا

## نصب

```bash
pip install fa-console
```

بک‌اند باکیفیت‌ترِ اختیاری:

```bash
pip install "fa-console[high-fidelity]"   # arabic-reshaper + python-bidi
```

یا کافی است فایل `fa_console.py` را داخل پروژه‌ی خودتان کپی کنید — این ماژول
عمداً تک‌فایلی و خودکفاست.

## شروع سریع

```python
import fa_console                      # همه‌ی پیکربندی همین‌جا انجام می‌شود

print("سلام دنیا!")                    # در هر ترمینالی درست دیده می‌شود
name = fa_console.fa_input("نام شما: ")  # نمایش زنده و درست هنگام تایپ
print(f"سلام، {name} جان!")            # داده منطقی، نمایش صحیح
```

مقداری که `input()` / `fa_input()` برمی‌گرداند همیشه متن **منطقی** یونیکد است:
مقایسه‌ها، `len()`، برش‌ها، عبارات باقاعده و ذخیره در فایل همگی متن فارسیِ سالم
می‌بینند. تبدیل نمایشی فقط در لحظه‌ی چاپ انجام می‌شود.

## کیبورد فارسی در برابر عربی

چیدمان‌های فارسی و عربی کیبورد، برخی حروفِ شبیه به هم را با **کدپوینت‌های متفاوت**
می‌نویسند: کیبورد عربی ي (U+064A) / ك (U+0643) می‌دهد در حالی که کیبورد فارسی
ی (U+06CC) / ک (U+06A9) می‌دهد. اعداد هم ممکن است فارسی (۰-۹)، عربی (٠-٩) یا ASCII
(0-9) باشند. `fa_console` این موضوع را در دو سطح حل می‌کند:

- **نمایش** — جدول‌های شکل‌دهی *هر دو* واریانت حروف را می‌پوشانند و موتور بازچینی،
  هر سه سبک عدد (به‌همراه جداکننده‌های `٫` و `٬` و `.`/`,` بین دو رقم، مطابق قاعدهٔ
  W4 یونیکد) را یک رشتهٔ عددی چپ‌به‌راستِ یکپارچه می‌داند. متنی که با هر چیدمانی
  تایپ شود، بدون کد اضافه درست نمایش داده می‌شود.
- **داده** — در سطح رشته، `"ی" != "ي"` است و همین بی‌سروصدا مقایسه‌ها، کلیدهای
  `dict` و جستجوهای پایگاه‌داده را بین کیبوردها می‌شکند. `fa_normalize()` شکل‌های
  عربی را به معادل فارسی می‌بَرد؛ حروفی که معنای مستقل دارند (مثل ة در برابر ه)
  هرگز دست‌نخورده می‌مانند.

```python
from fa_console import fa_normalize

fa_normalize("كتاب يخ")                       # -> 'کتاب یخ'
fa_normalize("سال ٢٠٢٦", digits="persian")    # -> 'سال ۲۰۲۶'
fa_normalize("۲۰۲۶", digits="ascii")          # -> '2026'
fa_normalize("۲۰۲۶", digits="arabic")         # -> '٢٠٢٦'

name = fa_input("نام: ", normalize=True)      # یکسان‌سازی هنگام خواندن ورودی
```

`fa_normalize` نگاشت ۱:۱ و خالص است — طول رشته همیشه حفظ می‌شود — و کاملاً
اختیاری است: تبدیل نمایشی بدون آن هم کار می‌کند.

## مرجع API

| عضو | کارکرد |
|-----|--------|
| `setup_console(force=False)` | اعمال کامل پیکربندی؛ idempotent. خروجی: `ConsoleSetupReport` |
| `fa_print(*args, **kwargs)` | جایگزین فارسی‌ساز برای `print()` |
| `fa_input(prompt="", normalize=False)` | `input()` فارسی با نمایش زنده‌ی درست؛ `normalize=True` حروف عربی ي/ك را به ی/ک می‌بَرد |
| `fa_normalize(text, digits="keep")` | یکسان‌سازی حروف عربی مشابه فارسی (ي/ك ← ی/ک)؛ با `digits` می‌توان سبک اعداد را هم یکدست کرد (`"keep"` / `"persian"` / `"arabic"` / `"ascii"`) |
| `is_visual_mode()` | `True` اگر تبدیل نمایشی فعال باشد |
| `get_console_info()` | دیکشنریِ وضعیت محیط (برای گزارش باگ عالی است) |
| `VisualStream` | پوشش شفاف استریم (کاربرد پیشرفته) |
| `FaConsoleError` | خطاهای عمدی سطح پایین (درون ماژول مدیریت می‌شود — fail-open) |

### عیب‌یاب خودکار

```bash
python fa_console.py      # از روی سورس
python -m fa_console      # از نصب pip
```

گزارش کامل محیط را چاپ می‌کند: انکودینگ‌ها، کدپیج کنسول، نوع ترمینال تشخیص‌داده‌شده،
موتور فعال و یک نمونه‌ی نمایشی. هنگام گزارش مشکل، خروجی همین دستور را ضمیمه کنید.

## چطور کار می‌کند؟

1. **لایه‌ی انکودینگ** — با `SetConsoleCP`/`SetConsoleOutputCP` (Win32) کنسول به UTF-8
   می‌رود؛ استریم‌های استاندارد به UTF-8 بازپیکربندی می‌شوند؛ `PYTHONUTF8=1` و
   `PYTHONIOENCODING=utf-8` برای فرایندهای فرزند تثبیت می‌شود.
2. **لایه‌ی نمایش** — فقط در conhost کلاسیک، پوشش `VisualStream` روی stdout/stderr نصب
   می‌شود و هر نوشته تبدیل می‌شود: حروف عربی/فارسی به شکل متناظر با بافت اتصال
   (منزوی/آغازین/میانی/پایانی، با پوشش کامل واریانت فارسی و عربیِ هر حرف مشترک —
   شامل پ چ ژ ک گ ی و همچنین ي ك) تبدیل و سپس سطر برای ترمینالِ چپ‌به‌راست
   بازچینی می‌شود؛ کلمات لاتین و اعداد صاف می‌مانند و پرانتزها آینه می‌شوند.
   جداکننده‌های عددی رشتهٔ عدد را نمی‌شکنند (`۱۲٫۵`، `1,000`، `10.5`).
3. **تشخیص** — تبدیل هر جا فعال می‌شود که خروجی، کنسول تعاملیِ فاقد پشتیبانی عربی
   باشد: conhost کلاسیک **و** ترمینال VS Code. Windows Terminal (`WT_SESSION`) و
   خروجی ریدایرکت‌شده کنار گذاشته می‌شوند — اولی خودش عربی را درست می‌چیند و دومی
   باید متن منطقی استاندارد بگیرد.

## پیکربندی

| متغیر محیطی | اثر |
|-------------|-----|
| `FA_CONSOLE_FORCE_VISUAL=1` | اجبار تبدیل نمایشی (اشکال‌زدایی) |
| `FA_CONSOLE_NO_VISUAL=1` | خاموش‌کردن کامل تبدیل نمایشی |

## سازگاری

| محیط | رفتار |
|------|-------|
| `cmd.exe` / PowerShell مستقل (conhost) | انکودینگ + تبدیل نمایشی + تایپ زنده |
| Windows Terminal | انکودینگ اصلاح می‌شود؛ نمایش بومی (ماژول کنار می‌کشد) |
| ترمینال VS Code | انکودینگ + تبدیل نمایشی (xterm.js چینش دوجهتهٔ مطمئنی ندارد) |
| JetBrains / IDLE | انکودینگ اصلاح می‌شود؛ ماژول کنار می‌کشد (غیر tty) |
| خروجی به فایل / پایپ | متن منطقی استاندارد UTF-8 — امن برای ابزارهای دیگر |
| لینوکس / مک | بدون عملیات (رفتار استاندارد) |

## محدودیت‌ها و پرسش‌های پرتکرار

- **هنگام تایپ در cmd حروف جدا جدا دیده می‌شوند.** `fa_input()` هنگام تایپ سطر را
  درست بازکشیدن می‌کند؛ echo خودِ کنسول برای پیام‌های سیستمی خارج از کنترل هر
  برنامه‌ای است.
- **بهترین نمایش ممکن؟** از [Windows Terminal](https://aka.ms/terminal) استفاده
  کنید — ماژول آن را تشخیص می‌دهد و شکل‌دهی را به خودش می‌سپارد.
- **تبدیل نمایشی داده‌ها را خراب می‌کند؟** خیر — فقط نمایشی است. مقادیر، مقایسه‌ها
  و فایل‌ها همیشه متن منطقی سالم دارند.
- **فارسی در ترمینال VS Code خراب دیده می‌شود.** این محدودیت xterm.js است و همین
  پکیج به‌صورت خودکار جبرانش می‌کند: همان تبدیل نمایشیِ کنسول کلاسیک در VS Code
  هم اعمال می‌شود (در صورت نیاز: `FA_CONSOLE_NO_VISUAL=1`).
- **از colorama یا tqdm استفاده می‌کنید؟** این کتابخانه‌ها هم `sys.stdout` را
  می‌پوشانند. `fa_console` را **قبل از** آن‌ها import کنید تا پوشش‌شان روی استریم
  دیداری بیاید و رنگ‌ها سالم بمانند.
- **زبان‌های دیگر راست‌به‌چپ؟** جدول‌های شکل‌دهی حروف عربی، فارسی و اردو/پشتو
  (ٹ ڈ ڑ ں ھ ہ ے) را پوشش می‌دهند و موتور برای حروف شناخته‌شده، مستقل از زبان است.
- **کاربرانم کیبورد فارسی و عربی را قاطی می‌کنند.** نمایش در هر دو حالت امن است —
  جدول‌های شکل‌دهی ي/ك را در کنار ی/ک دارند و اعداد با هر سبکی سالم می‌مانند.
  برای مقایسه و ذخیره‌سازی، `normalize=True` به `fa_input()` بدهید یا قبل از هش/جستجو
  `fa_normalize()` را روی مقادیر صدا بزنید تا یک کلمه با هر چیدمانی، رشتهٔ یکسانی بدهد.

## توسعه

```bash
git clone https://github.com/Padandish/fa-console.git
cd fa-console
python -m pip install build pytest
python -m build          # ساخت dist/
```

اجرای مجموعه تست:

```bash
python -m pytest tests -q
```

اجرای مثال تعاملی در هر کنسولی:

```bash
python example.py
```

اجرای گزارش کامل محیط:

```bash
python fa_console.py     # یا: python -m fa_console
```
